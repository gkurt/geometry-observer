Know when an element moves.

geometry-observer reports changes to an element's position and size, including the ones caused by other elements, like a sibling growing above it. It's built on CSS anchor positioning, so nothing polls, and no JavaScript runs while the page is idle.

npm install geometry-observer
Read the docs

This browser can't run the anchor-based mechanism, so the demos below use the fallback, which checks every frame. The API is the same. 

import { GeometryObserver } from 'geometry-observer';

const observer = new GeometryObserver((entries) => {
  for (const { target, rect, moved } of entries) {
    if (moved) placeTooltip(target, rect);
  }
});

observer.observe(button);
import { useGeometryObserver } from 'geometry-observer/react';

function HelpButton() {
  const ref = useGeometryObserver(([entry]) => {
    placeTooltip(entry.target, entry.rect);
  });
  return <button ref={ref}>Help</button>;
}

Elements moved by other elements

Drag a node or resize it from its corner. Overlapping nodes push each other apart, and the edges follow. The page only moves the node you drag. The others are pushed from the observer callback, and the edges and tooltips are drawn from the rects it reports. Hover a node for its tooltip, or click to pin it.

How it works

Three CSS features turn a layout change into a DOM event.

Anchor

Each target gets a hidden probe in the top layer. anchor() and anchor-size() keep the probe's box equal to the target's.

Transition

The probe's top, left, width and height have a 1ms transition.

Event

When layout moves the target, the probe's transition starts and fires transitionstart. The observer reads the target's rect. 

/* A simplified probe. The real one also has fallbacks and is a popover. */
.probe {
  position: fixed;
  position-anchor: --target;
  top: anchor(top);
  left: anchor(left);
  width: anchor-size(width);
  height: anchor-size(height);
  transition: top 1ms, left 1ms, width 1ms, height 1ms;
}

Scrolling doesn't change the probe's computed values, so it can't start a transition. The library covers it with one passive scroll listener for the whole page, and only re-measures targets inside the element that scrolled.

Most position changes come from something else in the layout: a sibling growing, content loading above, an ancestor's padding. ResizeObserver misses all of them.

Limits

The cost is per reflow, not per frame

Each probe is a box the browser lays out, so it adds a little to every reflow on the page. A rAF loop costs the same every frame instead. They break even at about five reflows per second in Chromium, and several times that in Safari, so under constant layout churn, one shared rAF loop is cheaper.

Safari misses CSS-only hiding

WebKit doesn't restyle a probe when its anchor goes away, so in Safari the observer also watches DOM mutations. Removal is always reported, and so is hiding through a style, class or other attribute change. A target hidden by CSS alone, like a :hover rule, isn't.

Composited animations lag slightly

During a composited transform animation, the reported rect trails by about half a frame. It's exact once the animation stops.

Firefox uses the fallback

Firefox accepts the CSS, but doesn't yet support transitions on anchor-driven changes. The observer detects this and checks every frame instead, with the same API.

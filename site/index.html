geometry-observer

Event-based element position and size observation. The layout engine tells you when something moved — no polling, no requestAnimationFrame loop, no observer re-arming, and no main-thread work at all while nothing changes.

The mechanism

anchor() and anchor-size() resolve a target's box into computed lengths on a hidden probe element. Computed lengths take part in transitions. A running transition dispatches a DOM event. That's the whole trick. 

/* the probe — a top-layer element mirroring #target's box */
#probe {
  position: fixed;
  position-anchor: --target;
  top: anchor(top);   left:   anchor(left);
  width: anchor-size(width); height: anchor-size(height);
  transition: top 1ms, left 1ms, width 1ms, height 1ms;  /* the tap */
}

The middle rows are the point. “A sibling above me grew, so I moved” is the most common way an element changes position, and it is exactly the case no observer reports.

Honest about the cost

Each probe is a real box the engine lays out, so probes add time to every reflow — including ones in which nothing they watch moved. A sampler instead pays on every frame, moving or not. The two meet at a low single-digit number of reflows per second.

So this is an idle-cost and coverage win, not a throughput win. For a page that mostly sits still — tooltips, popovers, connector lines, rulers, drag affordances — probes cost nothing and a sampler burns milliseconds every second forever. Under sustained layout churn, a single shared sampler is cheaper. track: 'size' roughly halves the probe's cost when you only need one axis.
